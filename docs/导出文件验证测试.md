# OMS 导出文件验证测试

## 背景

OMS 导出流程中有一个已知问题：前端选择"按筛选范围（一单多行）"格式偶尔不生效，导致出库导出实际产出库存数据。该问题已在 `trigger_export_task()` 中通过轮询等待 dropdown 渲染修复，但仍需一道**硬防线**在导出后验证数据类型正确性。

## 测试目标

验证 `data/raw/<日期>/<仓库>/<类型>/` 下每个导出 Excel 文件的列签名与预期数据集一致，杜绝数据类型错位流入后续同步链路。

## 数据集签名

OMS 三种导出格式的列结构完全不同，可通过关键列互斥检测：

| 数据集 | 必需列 | 禁止列 | 列数 | 格式 |
|--------|--------|--------|------|------|
| 出库 | `Outbound Order No./出库单号` | `Total Stock/总库存` | 60+ | 一单多行 |
| 库存 | `Total Stock/总库存` | `Outbound Order No./出库单号` | 21 | 全量查询结果 |
| 入库 | 待明确 | `Total Stock/总库存`, `Outbound Order No./出库单号` | ~20 | 全量查询结果 |

## 覆盖范围

9 个仓库 × 数据集组合，对应 `config/export_rules.yaml`：

| 仓库 | 出库 | 库存 | 入库 |
|------|------|------|------|
| DMILE | ✅ PASS | ✅ PASS | ❌ FAIL（库存数据） |
| OGR1808 | ✅ PASS | ✅ PASS | ❌ FAIL（出库数据） |
| YL888 | ✅ PASS | ✅ PASS | ❌ FAIL（出库数据） |

## 测试用例

### 1. `test_export_file_exists[warehouse-dataset]`
**验证点**：每个组合在最新日期目录下至少有一个 `.xlsx` 文件。
**跳过条件**：目录不存在时 skip（非 fail）。

### 2. `test_export_valid_excel[warehouse-dataset]`
**验证点**：文件可被 pandas 读取，且非空。
**跳过条件**：无文件时 skip。

### 3. `test_export_correct_dataset_type[warehouse-dataset]` ⭐ 核心
**验证点**：列签名匹配预期数据集类型。

检测逻辑：
1. 必需列缺失 → 可能格式选择失效
2. 禁止列出现 → 导出了错误的数据类型
3. 出库和库存特征列共存 → 数据混乱

**跳过条件**：无文件时 skip。

### 4. `test_export_no_mixed_datasets`
**验证点**：全量扫描 `data/raw/` 下所有 `.xlsx`，不存在同时包含出库和库存特征列的文件。

### 5. `test_export_outbound_status_column`
**验证点**：出库文件 Status/状态列全为"已出库"，确认筛选条件生效。

## 运行

```bash
# 全部验证
python -m pytest tests/test_export_validation.py -v

# 仅核心签名验证
python -m pytest tests/test_export_validation.py -v -k "correct_dataset_type"

# 程序化调用（输出 JSON）
python tests/test_export_validation.py
```


## 设计决策

### 为什么按 mtime 而非文件名选最新文件？
文件名包含 hash 后缀（如 `_7af714c4.xlsx`），旧文件可能在字母序后排到列表末尾被选中。用 `os.path.getmtime` 确保选到最近一次导出。

### 为什么用互斥列而非完整列头列表？
OMS 不同仓库可能有多余或缺失列，但出库/库存的核心特征列恒定不变。互斥检测比白名单更健壮。

### 入库为何同时禁止库存和出库特征列？
当前入库特征列尚未明确，但可以肯定的是入库单不应包含库存列表或出库单号。双禁止可捕获两类故障：导出了库存页面（DMILE 故障模式）和导出了出库页面（OGR1808/YL888 故障模式）。

### 旧文件怎么处理？
修复格式选择 bug 后，旧错误文件应手动删除。测试只验证最新文件（按 mtime），不会误判。

## 维护

新增仓库或数据集时，在 `KNOWN_COMBOS` 列表添加条目即可自动纳入参数化测试。如果入库特征列明确，在 `DATASET_SIGNATURES["入库"]["required"]` 填入对应列名。
